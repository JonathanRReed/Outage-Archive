          Use the [Timeline](/timeline/) when you want the outage record in
          date order. It is the fastest way to compare when major incidents
          happened and how patterns repeated across years.

          Use the [Archives](/archives/) when you want the broader incident
          register grouped by failure mode. The archive keeps routing failures,
          DNS problems, control plane incidents, CDN disruptions, telecom
          failures, and other shared-infrastructure cases together so they are
          easier to compare.

          Use [About](/about/) for the editorial method, source hierarchy, and
          project background. That page explains what belongs in the atlas, how
          disputed details are handled, and why this is a historical reference
          rather than a live monitoring dashboard.

          Use [Contact](/contact/) if you have a correction, a primary source,
          or a question about how an incident is categorized. Include the
          incident title, date, source link, and the specific detail that should
          be reviewed.

          A practical reading path is to start with the homepage for the core
          story, move to the timeline for sequence, then use the archive to
          compare similar failures side by side. If you are researching a
          specific infrastructure layer, scan the archive group headings first.
          If you are checking whether an incident belongs in the atlas, review
          the methodology notes before sending a correction.

          The atlas is organized around how failures spread, not only who was
          affected. That means the same vendor can appear in different contexts
          if the important lesson is routing, naming, identity, edge delivery,
          telecom dependency, physical infrastructure, or operational control.
          This finder page keeps those entry points close together without
          loading a client-side search bundle.

          For source review, prefer official incident reports, engineering
          postmortems, regulatory filings, routing analyses, and technical
          writeups with reproducible evidence. News coverage is useful when it
          establishes public impact, but the archive tries to keep technical
          claims tied to primary or specialist sources whenever possible.
